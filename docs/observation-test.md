# 测试观测接入，同时保留研究空间

接入行为与研究任务分别验证。准备应用、安装完整 Skill 和确认宿主访问权限，由安排测试的人完成；实验对话使用界面生成的简短接入信息，再接研究任务。研究提示词无需重复登记、恢复或节点组织规则。

## 应用准备与接入验证

使用独立研究目录和应用数据目录，并隔离旧版 `EXP_OBSERVER_STATE_DIR`，避免测试读取实际实验。

1. 由应用接入一次研究根目录（“连接 Agent → 研究目录”，或启动时 `--workspace PATH`），确认配置能跨重启保留。之后关闭服务。
2. 在研究目录调用 `init`，确认稳定实验 ID 和本地待交计划；重试不改变身份或元数据。禁止客户端写全局目录、禁止其访问服务，保留工作目录内写入权限。
3. 离线读取 `context`，确认明确表示不可用或待交，缓存带日期，没有把未知远端记录显示为空实验。
4. 新建一个实验子目录，用 `event --question '测试问题' --finding '实际测试发现'` 记录已有结果和证据。无需单独登记这个子目录；同一调用可创建问题与首条发现。确认结论属于该发现，结束只更新问题状态。`event` 不添加记录顺序边。
5. 启动同一地址的应用，不调用 `sync`。确认自动入库，保留祖先初始化的名称、原身份和时间。
6. 核对指标、原始证据和关系。普通记录顺序不冒充因果；明确的支持／反驳关系须来自实际记录。恢复不得重跑命令、重读变化的原文件、覆盖已有实验、跟随目录链接或越过接入范围。
7. 移除研究目录后新增一条暂存，确认恢复停止；再次接入才恢复，已有研究数据不删除。
8. 从研究工作目录调用一次 `status --project ID`，确认后台接收后的回执已变为 `synced`。禁用网络访问仍能读取；旧连接警告不应覆盖已确认状态。全项目 `context` 用 `hasNotes` 标示正文，带 `--node` 的上下文能读回原生分析。

只保存在实验文件中的结果不会自行入队。客户端执行或本地保存被宿主阻止时，需如实区分“未能暂存”和“已暂存待交”。应用无法越过宿主权限限制。手动 `sync` 是恢复工具，不是研究对话必须遵循的工作阶段。

自动检查覆盖本地新建、已有实验、离线结果、命令只执行一次、上下文缓存、并发重试及便携安装包。研究质量另看任务和证据，不从记录条数推断。

## 独立验收清单

下面是安排测试的人执行的功能验收，不加入研究 Agent 的任务提示词。继续使用独立应用数据目录、研究目录和测试项目 ID；所有构造结果、计数及截图均标为模拟。CLI 路径以本次安装的 Skill 为准，字段及协议细节见 [HTTP／数据契约](contract.md)。

1. **保留不同发现。** 对同一准确问题标题依次记录两个 `--finding`、一个 `--correction` 和一个 `--direction`。核对只有一个问题身份，四条变化各自保留标题、结论与分析，早期发现未被改写。问题与变化均为普通卡片，无自动父容器；关联分别为 `has_finding`、`has_correction`、`has_direction`。这是固定测试夹具的预期，不是实际研究的节点配额。
2. **问题身份与原子写入。** 两个互不相连的离线目录用同一 URL、项目及准确标题创建问题和不同发现；逆序恢复后问题只创建一次，保留首次登记的元数据，两条发现都存在。核对冻结操作包含 `node.ensure`。改变大小写应得到不同标题身份；祖先队列及已读取上下文中的准确标题应复用原身份，重名必须要求 ID。在批次末加入无效引用，确认整批回滚，未留下半个问题或发现。
3. **证据与重复测量。** 用一个会向本地标记文件追加字符的无害命令进行 `execute`，让两条发现以 `--evidence '准确捕获标题'` 共用其证据，确认命令只运行一次。另用 `execute --question '准确问题' --title '重复测量'` 增加一次运行，问题身份、既有结论及状态不重置。重试相同 `--request-id` 不再次运行；改变同一请求的内容应报冲突。不要为拆分发现重跑命令。
4. **分析、状态与恢复。** 用 `--notes-file` 输入含换行的 UTF-8 分析，暂存后改变或移走原文件，再恢复并读回冻结正文及证据。只更新问题为 `completed` 或 `paused`，确认没有新增完成节点或空运行。用 `status` 读取最新本地回执，已确认的记录显示 `synced`，不因旧连接警告退回 pending。
5. **包含与视觉。** 用低层 `apply` 创建一个普通父节点和子节点，再创建 `kind: group` 容器。确认普通父节点不会因 `parentId` 自动扩大为边框；`isContainer: true` 可让任意类型成为视觉容器，`isContainer: false` 可关闭 group 的默认容器。检查包含后代仍纳入上下文与用量范围。显式支持、反驳、修订边显示关系；旧版 `record` 的 `recorded_after` 只画淡虚线，无关系标签和流动动画。
6. **原生 Codex 导入。** 在隔离测试库中，把 [`codex-exec-usage.jsonl`](../tests/fixtures/codex-exec-usage.jsonl) 注册为 observed 命令运行的证据，并明确它是模拟日志。后台导入应保留两次完成 turn 的输入／输出／缓存计数，模型为 `unknown`，时间使用运行边界并标明 `timestampScope: execution`。重复附上相同运行的日志或重启导入器不增加计数；新运行即使复用同一 thread 也有独立身份。只有外部结果标记的快照不能凭原生日志建立命令身份。
7. **显式协议与未知值。** 分别通过 `run.metrics.expObserverUsage`、保留的顶层 JSON 及 `type: expobserver.usage.v1` 流事件输入同一个 v1 原始调用身份；只保留一份测量。验证实际零值保留、缺失计数和执行边界保持未知、未报告模型不从命令或提示词猜测。负数、布尔计数、累计口径或 `scope: agent` 声明产生警告且不阻塞其他有效记录；冲突身份不能覆盖已有计数。只有嵌套 `tokens`／`usage` 或孤立 `turn.completed` 时不导入。
8. **口径与证据边界。** 同时提供 agent 和 execution 用量，确认项目按口径与模型分别列示，节点详细视图保留两种来源，紧凑总数标明所选口径，不把被测任务算作主研究 Agent 完整成本。缓存单列，不再次叠加到输入。更改源日志不影响已保留证据；篡改保留副本应产生校验警告。缺少 Happy 数据、无效日志或不可读取的证据不得触发实验重跑，也不得阻塞其他有效导入。

相关自动检查可在项目根目录运行（不需要真实 Codex 调用、付费 API 或主机对话数据）：

```sh
python3 -m unittest tests.test_semantic_events tests.test_execution_usage tests.test_backend tests.test_host_usage -v
npx vitest run src/model.test.ts src/usage.test.ts
```

浏览器中的卡片、容器和连线表现还需在隔离测试项目中核对。通过模拟日志验收，不代表截图中 WG08／NI03 的原始日志已经找到或导入；确认旧实验用量必须另有对应的原始执行记录、合格日志和登记回执，不能凭截图或相似计数补写。

## 一段开放程度更高的字体实验提示词

下面的研究任务可接在“连接 Agent”生成的信息后面。它包含多种实际困难，给出研究目标和成本边界，把方法与后续选择交给证据。

```text
在一个全新目录中，研究交互式字形编辑中的轮廓对应：原始字形与编辑后的字形可能采用不同起点、不同子路径顺序和不同曲线分段，如何保留可靠的对应关系？

围绕一个可用实现，根据证据逐步改进。探索几何完全相同但分段不同的情况，以及轻微修改、重复或近似对称部件、部件插入删除对对应判断的影响。发现失败时追查原因，决定修正现有方法还是换路线；研究何时应承认歧义并拒绝强配。评价对应质量、信息保留和执行代价，说明适用范围。

用少量本地字体和必要的合成样本控制成本，只用 CPU，不训练模型或调用付费 API。保留可复现脚本、原始结果和说明现象的少量对比图。
```

这个任务不要求一定出现分支、转向或多次运行。若确实产生不同发现，Skill 分别保留已有事实并复用证据；若只有一次受控比较，就只记录它实际产生的问题与发现。研究方法、转向和交付由任务及证据决定。
