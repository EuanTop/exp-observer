# 测试观测接入，同时保留研究空间

接入行为与研究任务分别验证。准备应用、安装完整 Skill 和确认宿主访问权限，由安排测试的人完成；实验对话使用界面生成的简短接入信息，再接研究任务。研究提示词无需重复登记、恢复或节点组织规则。

## 接入验证

使用独立目录、独立数据目录和独立 `EXP_OBSERVER_STATE_DIR`，避免把测试数据写入实际实验。

1. 服务关闭时调用 `init`，确认有稳定实验 ID 和本地待交计划；重试不改变身份或已保存的元数据。
2. 离线读取 `context`，确认明确表示不可用或待交，缓存带日期，且没有把未知远端记录显示为空实验。
3. 记录已有结果及证据。可按实际发生的发现再增加记录，不以节点数量为目标。
4. 启动同一地址的应用，不调用 `sync`。确认记录自动入库，暂存身份和时间保持不变。
5. 核对原始指标和证据。恢复不得重跑命令、重新读取已变化的原文件、覆盖已有实验，或扫描未注册目录。

只保存在实验文件中的结果不会自行入队。客户端执行或本地保存被宿主阻止时，需如实区分“未能暂存”和“已暂存待交”。应用无法越过宿主权限限制。手动 `sync` 是恢复工具，不是研究对话必须遵循的工作阶段。

自动检查覆盖本地新建、已有实验、离线结果、命令只执行一次、上下文缓存、并发重试及便携安装包。研究质量另看任务和证据，不从记录条数推断。

## 一段开放程度更高的字体实验提示词

下面的研究任务可接在“连接 Agent”生成的信息后面。它复用已有小实验，给出研究问题和成本边界，把方法与后续选择交给证据。

```text
在当前字体实验仓库中，接着已有的轮廓规范化实验研究一个问题：几何形状只有轻微变化时，现有规则会不会让起点选择或子路径顺序发生很大变化？这种不稳定是否值得改进？

复用已有代码、字体和证据。第一轮仅用本地 CPU、一至两套已有字体和不超过 16 个字符，不训练模型、不调用付费 API。合理的几何变化、对照方式及是否尝试改进，由你根据观察决定，不预定要比较哪几种算法。

注意区分坐标数值变化与起点、轮廓顺序的突变。若尝试改进，同时考察完整曲线、孔洞及原始信息是否保留，不能只让序列看起来更相似。没有发现明显问题或改进不值得，也可以成为结论。

保留可复现脚本、原始结果和说明现象的少量对比图。最后回答：实际发现了什么、证据支持到哪里、目前是否值得修改预处理规则，以及还有什么不确定。新增产物放进独立目录，保留已有实验。
```

这个任务不要求一定出现分支、转向或多次运行。若确实产生新发现，Skill 保留已有事实；若只有一次受控比较，一条结果记录也可以准确反映研究。
