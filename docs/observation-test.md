# 测试观测接入，同时保留研究空间

接入行为与研究任务分别验证。准备应用、安装完整 Skill 和确认宿主访问权限，由安排测试的人完成；实验对话使用界面生成的简短接入信息，再接研究任务。研究提示词无需重复登记、恢复或节点组织规则。

## 接入验证

使用独立研究目录和应用数据目录，并隔离旧版 `EXP_OBSERVER_STATE_DIR`，避免测试读取实际实验。

1. 由应用接入一次研究根目录（“连接 Agent → 研究目录”，或启动时 `--workspace PATH`），确认配置能跨重启保留。之后关闭服务。
2. 在研究目录调用 `init`，确认稳定实验 ID 和本地待交计划；重试不改变身份或元数据。禁止客户端写全局目录、禁止其访问服务，保留工作目录内写入权限。
3. 离线读取 `context`，确认明确表示不可用或待交，缓存带日期，没有把未知远端记录显示为空实验。
4. 新建一个实验子目录，记录已有结果和证据。无需单独登记这个子目录。确认按实际捕获顺序保留关系，结论属于相应发现，结束只更新状态。
5. 启动同一地址的应用，不调用 `sync`。确认自动入库，保留祖先初始化的名称、原身份和时间。
6. 核对指标、原始证据和关系。普通记录顺序不冒充因果；明确的支持／反驳关系须来自实际记录。恢复不得重跑命令、重读变化的原文件、覆盖已有实验、跟随目录链接或越过接入范围。
7. 移除研究目录后新增一条暂存，确认恢复停止；再次接入才恢复，已有研究数据不删除。
8. 从研究工作目录调用一次 `status --project ID`，确认后台接收后的回执已变为 `synced`。禁用网络访问仍能读取；旧连接警告不应覆盖已确认状态。全项目 `context` 用 `hasNotes` 标示正文，带 `--node` 的上下文能读回原生分析。

只保存在实验文件中的结果不会自行入队。客户端执行或本地保存被宿主阻止时，需如实区分“未能暂存”和“已暂存待交”。应用无法越过宿主权限限制。手动 `sync` 是恢复工具，不是研究对话必须遵循的工作阶段。

自动检查覆盖本地新建、已有实验、离线结果、命令只执行一次、上下文缓存、并发重试及便携安装包。研究质量另看任务和证据，不从记录条数推断。

## 一段开放程度更高的字体实验提示词

下面的研究任务可接在“连接 Agent”生成的信息后面。它包含多种实际困难，给出研究目标和成本边界，把方法与后续选择交给证据。

```text
在一个全新目录中，研究交互式字形编辑中的轮廓对应：原始字形与编辑后的字形可能采用不同起点、不同子路径顺序和不同曲线分段，如何保留可靠的对应关系？

围绕一个可用实现，根据证据逐步改进。探索几何完全相同但分段不同的情况，以及轻微修改、重复或近似对称部件、部件插入删除对对应判断的影响。发现失败时追查原因，决定修正现有方法还是换路线；研究何时应承认歧义并拒绝强配。评价对应质量、信息保留和执行代价，说明适用范围。

用少量本地字体和必要的合成样本控制成本，只用 CPU，不训练模型或调用付费 API。保留可复现脚本、原始结果和说明现象的少量对比图。
```

这个任务不要求一定出现分支、转向或多次运行。若确实产生新发现，Skill 保留已有事实；若只有一次受控比较，一条结果记录也可以准确反映研究。
